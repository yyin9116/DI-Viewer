# DI-Viewer v1.1.21

## Fix

- **修复「所有按钮都点不动 / 控制桥接不可用」**：Tauri 2 的同步命令跑在主线程，而
  `get_state` 等命令内部调用 `window.url()` / `is_visible()`（它们会
  `run_on_main_thread` 并阻塞等待主线程）——主线程正被这条命令占着，于是自锁，
  第一个 IPC 就超时，随后整个 webview 的 JS 线程一起冻结。标签切换、新增标签、
  透明度、设置全部失效均由此引起。现全部 40 个命令改为 `async`（在 async 运行时执行，
  窗口调用正常回到主线程），实测 `get_state` 2ms、`switch_tab` 25ms、
  `set_opacity` 9ms、`new_tab` 128ms。
- **修复发布产物指向 dev server**：`Cargo.toml` 缺 `[features] custom-protocol`，
  裸 `cargo build --release` 的产物把窗口指向 `http://localhost:5173`。现已补上该
  特性并要求 release 构建显式启用（`tauri build` 自动带上）。
- **修复全屏/最大化后被吸回左上角**：窗口移动时的吸边逻辑会对**已最大化**的窗口调用
  `SetWindowPos`，Windows 的回应是把窗口还原并丢到显示器原点；同时持久化还记录了
  最大化下的 `-8,-8` 几何。现吸边与几何持久化都跳过最大化/全屏状态，
  实测还原后精确回到原位置（662,320 1236×799）。
- **修复快捷键页把面板标题顶出视口**：内容变高后面板无限向下增长，页签与标题被裁掉。
  现面板有 `max-h` 约束，内容区自己滚动。
- **热键冲突不再阻断启动**：此前任何一个全局热键被其他程序占用（本次是
  `Ctrl+Alt+P`）都会让 setup hook 返回错误、应用直接 panic 退出。现改为记录冲突、
  跳过该条并继续启动，设置页把对应行标成「被占用」并给出说明。

- **修复安装版启动即崩溃（退出码 101）**：安装版（NSIS/MSI）无法从磁盘定位 shared UI
  资源导致 panic。现将 shared UI 资产（app.css / app.js）与前端 dist 全部改为**编译期内嵌**，
  运行时零外部依赖——顺带根除打包器 `..` → `_up_` 目录压扁问题。
- **修复浏览器外壳（侧栏）从不渲染**：两个叠加的架构缺陷。
  1. home 页此前走 `file://`，而 Tauri IPC 层拒绝 `null` origin
     （"Origin header is not a valid URL"），外壳所有命令都无法调用。
     现将起始页内嵌进前端 dist 并改由**应用协议**伺服
     （Windows 为 `http://tauri.localhost/lucid-start-page/index.html`），
     IPC 走本地白名单，书签/历史按路径判定完全兼容。
  2. 外壳注入脚本在 document_start 阶段创建 DOM（此时 `documentElement` 为 null）
     直接 TypeError 死掉；且本 WebView2 构建对**动态插入的 `<style>` 不做解析**
     （`style.sheet` 恒为 null）。现改为 DOMContentLoaded 后挂载 + **constructable
     stylesheet**（`adoptedStyleSheets`）注入 CSS。
- **修复会话恢复复活远古 dev server 地址**：持久化里 `http://127.0.0.1:17333/...`
  之类的旧 home 每次 启动都被原样恢复（"127.0.0.1 拒绝连接"页）。会话清洗现在把
  任何路径指向起始页的 URL 一律折叠回当前 home。
- **应用图标与界面 Logo 统一**：按侧栏 Logo（竖条 + 半圆盘 + 圆点，slate-700）重新
  生成全套图标（ico / icns / png / Store Logo），任务栏、窗口、安装器图标同步更新。

## Changed

- **标签页改为「一个窗口 + 每标签一个子 webview」**：此前 20 个「标签」只是同一个窗口里的一串 URL，
  点任意标签都会 `navigate`，等同整页重载（滚动位置、表单、播放进度全丢）。1.1.21 中途曾把每个标签
  做成一个独立窗口，靠 show/hide 伪切换——那不是标签页，是多个窗口：N 份窗口边框、N 份外壳，
  而且置顶、透明度、点击穿透、吸边、几何持久化都得以「循环作用于所有窗口」的方式补，任何新建窗口
  都会带着过期状态出生。现改为**真标签结构**：一个原生窗口，标签是它的子 webview
  （`browser` / `browser-N`，label 稳定不随索引变化），切换只是换前景子 view，页面保持存活；
  关标签只销毁该子 view；窗口级属性只作用于唯一的那个窗口。
- **设置面板纳入设计系统并打包字体**：面板此前用的是自造的字号与配色。现按 Ardot
  `737378809166340`（Sec/RadiusType）重做：Sarasa Gothic SC、11/12/13/16/21、letter-spacing 0、
  仅 Regular + Semi Bold；控制台底色 #F3F6FB / 卡片 #FFFFFF / 正文 #1F2937 / 弱化 #5B6470 /
  分割线 #D6DEEA / 强调 teal-700。**Sarasa 不是 Windows 自带字体**，所以两个权重
  （Regular / Semi Bold，WOFF2，SIL OFL）已打进安装包，由内置的 `diviewer://` 协议供给，
  页面侧用 `FontFace` 注册——不再出现「拉丁走 Segoe UI、中文走雅黑」的基线错位。
  缺字时回落到 Noto Sans SC（同为 Source Han 骨架）。
- **快捷键改成两层模型，不再劫持打字**：旧默认把 `R` `0` `P` `5` `6` `7` `8` `O` 注册成**系统级**
  全局热键，任何程序的输入框里敲这些字符都会被吞掉。现在按「有没有修饰键」分两层：
  - **带修饰键** → 注册为系统热键，只留给「窗口隐藏/穿透时也必须能按」的动作（显示隐藏、穿透、退出）。
  - **不带修饰键** → 只做应用内匹配。焦点在输入框 / 文本域 / contenteditable、输入法正在拼写
    （`isComposing` 或 `keyCode 229`）、或按着 Ctrl/Alt 时自动跳过，且事件不会传给页面。
  因此 `R`（录制）、`5`/`6`（快退快进）、`7`/`8`（透明度）、`` ` ``（播放暂停）、`O`（全屏）
  可以放心用回裸键；`0` 这种要「窗口看不见时也能按」的仍保留组合键。配置 schema 升到 3：
  v1 裸键配置与 v1.1.21 自动生成的 `Ctrl+Alt+*` 配置会被识别并迁移到新默认，**用户自己改过的绑定原样保留**；
  设置页新增「启用全局快捷键」总开关、每个绑定标注「全局 / 应用内」、重复绑定检测。
- **新增找回窗口机制**：固定快捷键 `Ctrl+Alt+Shift+R`（不受总开关影响）与托盘菜单
  「找回窗口」都能把透明度恢复 100%、关闭点击穿透、取消最小化并重新聚焦；窗口离开所有
  显示器时自动居中，锁定位置会同步解除（否则会被吸附回越界坐标）。启动时也会做一次越界检查。
- **设置面板重做并纳入设计系统**：原设置面板在设计文件中没有对应规格，内容也停在旧功能。
  现按 `Shell` 令牌补齐 Light/Dark 规格（面板 368 / r26 / 内边距 16，4 组页签），代码同步
  重写为「外观 / 窗口 / 快捷键 / 恢复」四页，新增总开关、找回窗口入口、修饰键校验与重复检测。
- **外壳视觉修正**：侧栏收起时把底色/描边从「宽度动画的盒子」移到内部面板上，消除收起过程
  的白边闪烁（顶栏同样的不透明遮罩一并移除）；tab 条引入 `chrome-strip` / `tab-active` /
  `tab-idle` 令牌，选中态由「白底压白底」改为「灰底上的抬升面」，明暗两种主题对比都够。

- `DI-Viewer-v1.1.21-windows-x64-setup.exe`：NSIS 安装器（推荐，用户级安装）。
